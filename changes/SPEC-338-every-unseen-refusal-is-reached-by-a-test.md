## Objective

Close the EC-5 gap the `B6-EXIT` gate evaluation measured at b4562e7a3ab4390dac0992032ebe384d0af5082a: the SPEC-337 function-body probe removed each refusing RAISE in an app function body, and 360 removals passed every test. Four behavioural refusal tests reach 347 of those 360 refusals, each asserting its sqlstate and message: Test 195 the 71 refusals of a caller with no active tenant, Test 196 145 refusals by a direct call, Test 197 91 that need a prepared state, another actor or the system caller, and Test 198 40 trigger refusals. The other 13 are unreachable, each for a recorded reason. The probe found CHAT-5, an invalid conversation transition refused as `permission denied: <NULL>` instead of its own message; Test 196 pins it OPEN, and the register, the surface disposition and the plan record it. The plan records EC-5 met as measured; `B6-EXIT` stays `NEXT`, because recording a boundary as reached is its own contract.

## Business Reason

EC-5 requires that an invariant held in a database control be proven by a test that fails when the control is removed. At b4562e7a3ab4390dac0992032ebe384d0af5082a (277 migrations, 194 test files and 3609 assertions), 360 refusing RAISE statements could be lowered to NOTICE with every test still passing, so no test saw those refusals. A refusal no test can see is not proven (DEC-33 rules 9 and 12), and EC-5 was the last partial exit criterion the gate evaluation recorded.

## Risks

A refusal test proves that the refusal is reached with its recorded sqlstate and message, not that no other path admits the same input; the domain tests keep that evidence. A message another layer repeats could be raised by a different function; where that happens, Tests 197 and 198 assert the function that refused (the innermost context frame). Every preparation runs inside a subtransaction that is always undone, so no prepared fact survives into the next assertion. An OPEN pin records a defect, not desired behaviour: the CHAT-5 assertion fails when the defect is repaired, so the repair updates the test and the register together, as Test 194 does. This contract changes no migration, function, policy, grant or database object.
