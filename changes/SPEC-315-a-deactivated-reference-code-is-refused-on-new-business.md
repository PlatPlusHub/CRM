## Objective

Batch 6 Slice 59 refuses a deactivated nationality, country, currency or language on a new create or on a change of that field, while every row that already holds it keeps it and stays editable (REF-2). It records `nationalities`, `countries` and `currencies` AUDITED and moves the `languages` row to the new rule.

## Business Reason

- **Selection.** `scripts/batch6_select_target.ps1` at `c4876c8`, on the live local catalog, ranks `nationalities`, `countries` and `currencies` next (Exposure 0, all NOT-RECORDED). Under the owner's instructions of 2026-11-16, this slice groups the selector's next three surfaces in one contract per product: they share one shape (a reference list a row names by code) and one fixture. The manifest's Next capability names that selector, never a copy of its result.
- **Why it matters.**
  - The four lists are written only by migrations (`postgres`). `authenticated` holds SELECT only under `read_all_authenticated`; `service_role` holds REFERENCES, TRIGGER and TRUNCATE only; `anon` and `orvion_integration` hold nothing. Each list carries `is_active`.
  - The foreign keys into them (ON DELETE RESTRICT) check existence only, and the readers `app.create_passenger`, `app.create_booking_item` and `app.create_quotation` never read `is_active`. So a value the platform has retired is still written onto new business.
  - The catalog families already follow the rule this slice carries: `app.enforce_catalog_codes` (on about 40 tables) refuses an inactive value at a create or a change of that column, and skips an unchanged column on UPDATE so that a historical row stays editable.
  - No spec defines the behavior: SPEC-025 and SPEC-037 only define the columns, `is_active` included. SPEC-314's Positions recorded the current fact for languages and carried the question here. The owner's policy of 2026-11-18 answers it and supersedes that position: existing rows keep a deactivated value; a new create, or a change of that field, refuses it.
- **Measured at `c4876c8`** on the local stack. The fixtures were one tenant with an owner at `aal1` and `aal2`, an employee, a trainee, a branch manager and a finance manager, plus another tenant's owner at `aal2`, `service_role`, `postgres` (for integrity only) and anonymous REST; 84 probes.
  - **REF-2 (Low).** With the value deactivated, all ten member-chosen columns accepted it at create, each after a positive control with the value active. Nine accepted it at a change of that field; the tenth, `quotations.currency_code`, is already held by `app.guard_quotation_integrity`. An existing row holding the value was kept through an edit of another field. Business already made in a deactivated currency still settles: a quotation item, an invoice and its payment, a refund.
  - **Why REF-2 is Low.** Nothing crosses a tenant or role boundary and no amount moves; a retired value is written onto new business.
- **The repair: one migration, `20261118120000` (REF-2).**
  - `app.enforce_reference_codes()`: the `app.enforce_catalog_codes` rule over (column, table) pairs. It is plpgsql, SECURITY DEFINER with an empty `search_path`, and EXECUTE is revoked from public. It skips a null and, on UPDATE, a column whose value is unchanged. It refuses an inactive value (23514, `check_violation`) and leaves an unknown code to the foreign key.
  - Eight BEFORE INSERT OR UPDATE triggers `<table>_enforce_reference_codes`: `passengers` (nationality, passport issuing country), `bookings` (destination country), `customers` (preferred language, credit limit currency), `suppliers` (credit limit currency), `quotations`, `booking_items` and `financial_accounts` (currency), and `tenants` (default currency).
  - No grant, policy, constraint, foreign key, existing trigger or function body changes.
- **Existing files that move, each for a stated reason.**
  - `supabase/tests/180_plans_languages_and_conversion_cursor_test.sql`: assertion 19, which asserted that a new customer is accepted a deactivated language, now expects the refusal (23514) by the owner's policy; its header and section title say so. `plan(20)` is unchanged.
  - `reports/master/MASTER_API_CONTRACT.md` is regenerated by Step 9 and stays equal to the baseline: no table, policy, RPC or grant moves.
- **Swept and found sound, pinned rather than changed:**
  - Every member write to `nationalities`, `countries` and `currencies` (insert, deactivate, delete) is refused 42501 at every role, tenant and second factor; `service_role` is refused on every write; a code in use cannot be deleted (RESTRICT) and a malformed one is refused (check); anonymous REST is refused (401).
  - The trainee and the other tenant read every row, as the shared lists intend.
- **Recorded positions, not repaired (in the migration's header):**
  - `invoices`, `payments`, `payment_allocations`, `refunds`, `journal_entry_lines` and `quotation_items` carry the currency of what they settle and are not guarded.
  - `exchange_rates` records a historical fact; `offline_conversions`, `campaign_daily_metrics` and `company_assets` record reported facts.
  - `booking_item_passengers.manifest_passport_issuing_country_code` is a snapshot with no foreign key.
  - The contact-method family mismatch on `customers` (probed in this slice) is its own later contract.
- **Latent on Primary.** `vrvtsxexkiiiivlkdxzp` holds 82 nationalities, 82 countries, 18 currencies and 20 languages, none inactive, and no tenant, customer, passenger or booking (read-only, 2026-11-18, ledger 269). No stored row is affected and no data repair is needed.
